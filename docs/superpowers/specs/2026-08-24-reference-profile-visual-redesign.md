# 个人求职门户高保真单页视觉重构设计

## 1. 目标与边界

本轮将现有求职门户重构为高保真单页个人品牌站。视觉骨架、页面节奏和交互方式参考 `xianchaoqian.com`，但不复制对方源码、文字、肖像或专属素材。所有公开内容继续使用江俊杰本人的教育、实习、系统设计、开源贡献和博客数据。

核心目标：

- 让 `cxzg007 Profile` 成为首屏最强视觉标识，`江俊杰 / Jiang Junjie` 为次级署名。
- 将页面从分散的卡片式作品集改造成连贯的单页工程叙事。
- 以三张粘滞堆叠实习卡作为求职展示主线。
- 用项目标签页、Semantica 开源板块、荣誉和博客补足工程深度与公开影响力。
- 移除 Three.js/WebGL，使用轻量 CSS 与浏览器原生能力实现动态效果。

本轮以 `1280–1920px` 桌面端为精修范围。移动端不新增复杂表现，仅保证现有内容可读、操作可用和无横向溢出。

## 2. 参考站设计拆解

参考站的核心视觉特征为：

- 高度约 `54px` 的固定半透明导航，带极细内高光。
- 首屏使用暖灰粉到近黑的纵向渐变，并配合柔和径向光晕。
- 超大、低字重、浅米白渐变标题占据首屏中心。
- 胶囊形主次按钮；主按钮为浅色实体，次按钮为透明玻璃表面。
- 主内容宽度约 `1100px`，主要卡片圆角约 `20–22px`。
- 内容区使用纯黑或深石墨背景，通过轻描边、内高光和品牌色局部光晕区分层级。
- 实习经历使用粘滞卡片堆叠，左右图文交替。
- 项目内容使用横向标签页和大型内容舞台。
- 动效主要来自淡入、上移、滚动粘滞、轻微缩放与局部节点点亮，而不是高强度三维动画。

## 3. 视觉系统

### 3.1 色彩

- 页面主背景：`#060909` 到 `#0b0d0e`。
- 首屏上部：灰粉棕 `#867174`。
- 首屏中部：暖灰褐 `#7a676a`。
- 首屏下部：橄榄黑 `#10120f` 到 `#020302`。
- 主文字：`#fff3f0`。
- 次级文字：`rgba(255, 255, 255, 0.68)`。
- 卡片表面：`#17171b` 到 `#0e1016`。
- 通用卡片描边：`rgba(235, 239, 255, 0.16)`。
- 通用暖色高光：`#f7708e`。
- 浅色按钮：`#fffaf6` 到 `#d9d2ca`。

京东、智元机器人、中国船舶集团和 Semantica 的品牌色仅在对应卡片内部使用，不改变全站基础主题。

### 3.2 字体与尺寸

- 正文沿用 Inter、系统中文无衬线字体栈。
- 首屏标题使用 Inter Display 风格，桌面字号约 `clamp(5.5rem, 9vw, 7.5rem)`，字重控制在 `420–460`。
- 区域标题采用两行编辑式排版，主句为浅色，强调句使用暖灰粉或品牌色。
- 状态、编号、时间和工程节点使用等宽字体。
- 正文行高保持 `1.7–1.85`，避免大卡片内信息拥挤。

### 3.3 表面与空间

- 桌面内容宽度为 `min(1100px, calc(100% - 48px))`。
- 主要卡片圆角为 `20–22px`，内部小卡片为 `10–14px`。
- 卡片使用一层品牌径向光晕、一层深色渐变表面、一条低透明度描边和一条顶部内高光。
- 阴影仅用于大卡片和主要按钮，避免所有元素同时发光。

## 4. 页面信息架构

页面按以下顺序组织：

1. `cxzg007 Profile` 首屏。
2. 个人信息与教育背景。
3. 京东、智元机器人、中国船舶集团 722 研究所三张粘滞实习卡。
4. 后端工程与系统设计标签页。
5. Semantica 开源贡献。
6. 荣誉证明。
7. 技术博客。
8. 联系方式。

固定导航对应：`信息`、`实习`、`系统`、`开源`、`荣誉`、`博客`、`联系`，并保留 GitHub 与简历入口。当前区域进入主视口时更新导航激活状态。

## 5. 首屏与个人档案

首屏高度约为 `1100–1150px`，分为背景、主内容和悬浮档案三层。

### 5.1 背景层

- 使用暖灰粉至近黑的纵向渐变。
- 叠加低透明度噪点与顶部径向光晕。
- 鼠标移动只改变光晕位置，不触发大幅视差。

### 5.2 主内容层

- H1：`cxzg007 Profile`。
- 一句话定位：可靠 Agent、知识图谱与后端系统工程。
- 主按钮：`查看实习`。
- 次按钮：`下载简历`。

### 5.3 悬浮档案层

悬浮档案面板展示：

- `江俊杰 / Jiang Junjie`。
- `AI Agent / 后端开发`。
- 2027 届校招状态。
- 同济大学两行教育经历。
- 邮箱、GitHub 与简历入口。
- 工程成长路径：`通信工程 → 后端系统 → Agent / 知识图谱 → 可靠 AI 工程`。

原有 3D Agent 网络与 Three.js 依赖从首页移除。首屏进入时依次执行标题上浮、按钮显现和档案面板展开；档案面板只应用轻微悬浮和倾斜。

## 6. 个人信息区

个人信息区承接首屏档案，使用深黑背景和两列布局：

- 左侧为两到三段简洁的工程定位与求职叙事。
- 右侧为结构化资料表，包括姓名、技术 ID、学校、学历、毕业年份、目标岗位和技术方向。

不新增独立教育板块。教育经历在首屏档案与信息区各出现一次：首屏负责快速识别，信息区负责完整结构化阅读。

## 7. 粘滞实习卡

### 7.1 交互结构

- 每张卡桌面高度约 `610px`。
- 卡片在滚动到导航下方时进入 sticky 状态。
- 后一张卡上推覆盖前一张，形成履历堆叠。
- 三张卡左右图文方向交替。
- 不再默认折叠关键内容；核心职责和交付直接可见。
- 详细背景可以放入卡片内部的二级说明区，但不依赖展开操作才能理解经历价值。

### 7.2 京东

- 价值标题：构建本体驱动的 AI 数据智能平台，让 LLM 在受控语义边界内完成查询、规则生成与业务回写。
- 工程链路：`业务 Schema → 本体语义层 → 受控 Agent 执行`。
- 能力记录聚焦本体映射治理、多跳关系推导、确定性回写与缓存失效治理。
- 使用京东红作为局部径向光晕和状态色。

### 7.3 智元机器人

- 价值标题：为机器人多传感器数据与企业知识资产构建可靠的流式回放和 Agent 记忆后端。
- 工程链路：`多源机器人数据 → 流式回放 / 知识抽取 → 可恢复 Agent 服务`。
- 能力记录明确拆分 `clip-player` 与 `agibot_retriever`。
- 使用智元蓝青色作为局部视觉强调。

### 7.4 中国船舶集团 722 研究所

- 价值标题：面向海上通信网络组建与受损恢复，完成算法建模、仿真验证和无人机集群通信方案论证。
- 工程链路：`通信场景建模 → 网络重构仿真 → 方案验证交付`。
- 能力记录聚焦通信链路、网络恢复、仿真指标和方案文档。
- 使用 CSSC 蓝作为局部视觉强调。

## 8. 系统设计标签页

系统设计区使用四个标签：

- `Ontology Agent`
- `Streaming Backend`
- `Knowledge Memory`
- `Semantica`

每个标签页由左右两部分组成：

- 左侧：问题背景、个人职责、关键决策、技术栈和公开入口。
- 右侧：架构链路、数据流或状态机的抽象视觉。

切换时使用淡出、`20–30px` 位移和节点顺序点亮。标签页必须支持方向键、Tab 和 Enter/Space 操作，并通过 `aria-selected`、`aria-controls` 与 tabpanel 语义关联。

## 9. Semantica 开源板块

Semantica 同时出现在系统标签页和独立开源板块中：标签页解释技术架构，独立板块展示项目背景、公开贡献和影响力。

- 使用官方 Logo。
- 身份为 `Open-source Contributor · cxzg007`，不暗示维护者身份。
- 项目背景：Semantica 是面向 AI Agent 的图原生上下文与可审计基础设施，为知识图谱、决策追踪、确定性推理、本体治理与来源追溯提供统一能力。
- 能力链路：`ContextGraph → RDF / SHACL → Temporal Graph → Rule Inference → cxzg007`。
- 展示 7 个公开 PR、2 个已合并 PR 和快照日期。
- 提供项目仓库和贡献复盘文章入口。

PR 内容使用结构化模型：

```ts
type OpenSourceContribution = {
  number: number;
  status: "merged" | "open" | "review";
  summary: string;
  url: string;
};
```

已合并数量从贡献数组计算，不再从展示文案解析或手工重复维护。

## 10. 荣誉证明

荣誉区使用两列长卡：

- 开源影响力：`GitHub Trending · #1 Repository of the Day`、`Trendshift · Python #3 Repository of the Week`。
- 教育与竞赛：国家励志奖学金、大唐杯上海市二等奖、本科排名 `12/62`。

每项荣誉展示名称、来源、时间或分类和一句说明。Semantica 排名依据用户提供截图展示，不称为 GitHub 官方认证奖项。

## 11. 技术博客

首页博客区采用横向内容舞台：

- 左侧显示标题、摘要、标签、日期和阅读入口。
- 右侧显示抽象代码窗口、架构缩略图或文章主题图形。
- 支持上一篇和下一篇切换。
- 首页只消费现有 Markdown/MDX 索引，不增加 CMS 或管理后台。
- 文章详情页继续使用现有博客路由和阅读模板。

当文章只有一篇时，隐藏无效的翻页按钮，不伪造内容。

## 12. 联系区

页面以大面积深色联系区收尾，中心文案为：

> Build reliable agent systems together.

展示邮箱、GitHub、简历下载和 2027 届校招状态。仅保留与求职和技术协作相关的入口，不添加无关社交平台。

## 13. 组件与数据边界

主要组件：

- `ProfileHero`：首屏标题、定位和操作。
- `ProfileDock`：身份、教育、联系方式与成长路径。
- `StickyInternshipStack`：粘滞堆叠布局。
- `InternshipStoryCard`：单段实习品牌叙事。
- `SystemProjectTabs`：标签状态和键盘交互。
- `ArchitectureStage`：系统链路视觉。
- `OpenSourceShowcase`：Semantica 背景、贡献和链接。
- `HonorGallery`：开源与教育荣誉。
- `WritingStage`：首页文章切换。
- `ContactStage`：联系与简历入口。
- `PageMotionController`：导航激活、进入视口状态和轻量视差。

首页以服务端组件为主。仅标签页、文章切换、导航状态和滚动增强使用客户端组件。所有公开数据继续来自本地 JSON/MDX。

内容契约同时收紧：

- `profile.technicalId` 为必填非空字符串。
- PR 编号、状态、摘要和 URL 为独立字段。
- Logo 路径、替代文本和文件存在性继续在构建期校验。
- 页面不显示 `authenticated-user query`、`简历列出` 等内部核验过程文案。

## 14. 动效与性能

- 使用 CSS transition、IntersectionObserver 和 requestAnimationFrame。
- 页面只保留一个滚动控制边界，不允许各个板块分别注册无界滚动监听。
- 动效仅修改 `transform`、`opacity` 和 CSS 自定义属性，避免滚动时触发布局计算。
- 实习粘滞卡使用浏览器原生 sticky，不通过 JavaScript模拟定位。
- 首页移除 Three.js、React Three Fiber 及其动态分包。
- 公司 Logo 使用 Next.js `Image` 组件，并保持原始比例。
- 博客列表和详情继续与首页动效代码隔离。

## 15. 降级与错误处理

- JavaScript 不可用时，身份、教育、实习、开源、荣誉和联系内容仍在服务端 HTML 中可读。
- 不支持 sticky 时，实习卡退化为普通纵向卡片。
- `prefers-reduced-motion: reduce` 时禁用视差、堆叠缩放和顺序点亮。
- Logo 文件缺失或为空时生产构建失败。
- 标签页默认服务端渲染第一项；交互失败不影响第一项阅读。
- 外部 GitHub 或文章链接异常不阻塞首页渲染。
- 单篇博客场景不显示无效轮播控制。

## 16. 验收标准

### 16.1 视觉与内容

- 在 `1280×800`、`1440×900` 和 `1920×1080` 下完成桌面验收。
- `cxzg007 Profile` 是全站最大标题，真实姓名和岗位信息可在首屏访问。
- 三张实习卡使用清晰、未变形的公司 Logo，并正确完成粘滞堆叠。
- 三段实习均显示核心价值标题、系统链路和三项高价值贡献。
- 系统设计标签页完整展示四类主题。
- Semantica 显示官方 Logo、项目背景、结构化 PR、两项排名和公开入口。
- 荣誉、博客和联系区均使用参考站一致的深色舞台语言。

### 16.2 可访问性与降级

- 键盘可以访问导航、CTA、所有标签页、博客切换和外部链接。
- 文本与交互状态达到 WCAG AA 对比度。
- 公司和项目 Logo 具有准确替代文本。
- 减少动态效果时内容完整、布局稳定。
- JavaScript 禁用时核心求职信息可阅读。

### 16.3 性能与工程门禁

- 首页不加载 Three.js、React Three Fiber 或 WebGL 场景代码。
- 无持续无界监听、明显布局抖动和横向溢出。
- 通过 lint、TypeScript、内容验证、生产构建、单元测试、Playwright、无障碍和视觉回归测试。
- Vercel 生产构建继续使用现有 pnpm、Node 和站点 URL 合同。
- 当前博客路由、简历下载、SEO、RSS、sitemap 和公开链接保持可用。

## 17. 非目标

- 不复制参考站源码、文字、头像、摄影作品或私有素材。
- 不新增 CMS、数据库、登录、管理后台或在线编辑功能。
- 不新增复杂移动端动画。
- 不虚构实习指标、开源状态、排名或荣誉。
- 不改变现有 Next.js + Vercel 部署架构。
