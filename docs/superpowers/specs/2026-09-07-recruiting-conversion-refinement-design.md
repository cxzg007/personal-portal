# 个人门户招聘转化精修设计

## 目标

在不推翻现有暖色品牌语言的前提下，把首页从“完整履历陈列”收紧为“招聘者可在十秒内理解的工程能力入口”。页面继续面向 2027 届 AI Agent / 后端开发校招，桌面端优先；不在本轮重新设计移动端，不虚构指标、职责、PR 状态或项目荣誉。

## 成功标准

- 首个桌面视口同时说明技术身份、真实姓名、学校/学历/毕业年份、求职方向，并提供实习、简历和 GitHub 三个明确入口。
- 首页删除重复的个人信息区，滚动路径按“首屏—实习—系统项目—开源—写作—联系”展开。
- 三段实习在默认状态下都能快速扫读公司、岗位、时间、核心职责与最多三条核心成果；完整工程细节可按需展开。
- 开源区域优先展示项目背景、已合并数量、贡献方向和三项代表性 PR，其余已合并 PR 可展开查看。
- GitHub Trending / Trendshift 荣誉只在具备可追溯来源并能明确归属于 Semantica 项目时展示；当前无结构化证据，因此本轮不新增荣誉文案。
- 页面保留暖色体系，但通过深咖啡/砖红开源区形成视觉高潮；所有新增动效服从 `prefers-reduced-motion`。
- 修复重复 `id` 与重复标题层级，保持键盘和辅助技术可用。

## 信息架构

### 1. 首屏

主标题只显示 `cxzg007`，移除模板化的 `Profile`。上方保留 `RELIABLE AGENT · BACKEND SYSTEMS`，下方使用“构建可靠 Agent 系统”方向的短句。真实姓名、目标岗位、两段同济教育背景继续放在首屏身份卡中，并压缩高度，使核心信息尽量进入 1280×720 的首个视口。

首屏操作区包含：

1. `查看实习`：跳转 `#internships`；
2. `下载简历`：打开 `/resume.pdf`；
3. `GitHub`：打开公开主页。

### 2. 实习经历

保留现有三家公司与官方 Logo，默认卡片展示：公司/团队、岗位、时间、价值标题、业务背景、职责边界、最多三条核心成果和技术栈。核心成果直接复用已验证内容，按“动作—技术难点—工程价值”压缩，不引入未经证明的百分比或规模数据。

原有 journey 继续作为视觉化的三阶段工程链路。超过三条的详细 highlights 放入原生 `<details>`，标签为“查看工程细节”，兼顾无 JavaScript 可用性与键盘操作。

### 3. 系统项目

保留四个项目 Tab 与“输入约束—工程决策—可验证结果”的三节点结构。增强选中状态、节点连接线和切换过渡，不增加新的业务事实。键盘方向键、Tab 语义和 reduced-motion 行为保持现状。

### 4. 开源贡献

开源区改为深咖啡背景和浅色内容卡，首先展示 Semantica Logo、项目背景、`已合并 PR` 数量及贡献方向。代表性 PR 固定从已合并贡献中选择三项：依赖层并行执行、ContextGraph 标准适配器、SHACL 真实约束解释。若目标 PR 数据缺失，则按已合并列表顺序补足，不产生空卡。

其余已合并 PR 收入 `<details>`。保留仓库和贡献复盘链接。开放 PR 不计入已合并数量，也不混入代表性成果。

### 5. 技术写作与联系

当前只有一篇文章，因此使用“精选工程复盘”单卡布局，不模拟轮播。联系区只保留一个可见标题，加入简历、邮件和 GitHub 三个收口动作。

## 视觉与动效

- 延续奶油黄、浅杏、鼠尾草绿和陶土红。
- 开源区使用深咖啡底，统计数字和选中状态使用暖橙色，建立页面第二视觉焦点。
- 首屏标题保留轻微滚动位移；实习卡进入视口时按 Logo、标题、成果顺序渐显；项目节点随选中 Tab 依次点亮。
- 不新增 Three.js 或其他重型依赖；动画仅使用现有控制器、CSS transform/opacity 和 requestAnimationFrame 节流状态。
- reduced-motion 下禁用位移、分步渐显和节点动画，内容立即可见。

## 组件和数据边界

- `ProfileHero` 负责主标题和三项 CTA；`ProfileDock` 继续负责姓名、教育和联系方式。
- 删除首页对 `ProfileInfo` 的渲染；组件文件可删除，相关测试同步迁移到首屏断言。
- `InternshipStoryCard` 只消费现有 internship 数据，通过展示策略压缩内容，不修改事实模型。
- `OpenSourceShowcase` 在组件内部派生代表性/剩余已合并 PR；派生逻辑抽为纯函数并单测。
- `WritingStage` 和 `ContactStage` 不再产生与外层章节重复的 `h2`。
- `site-content.json` 仅调整已有文字的顺序和压缩表达；所有事实边界保持不变。

## 可访问性与错误处理

- 页面中每个 `id` 唯一，外层章节由唯一 `h2` 标记，卡片从 `h3` 开始。
- `<details>/<summary>` 采用浏览器原生键盘行为，并提供可理解标签。
- 外链继续使用 `target="_blank"` 与 `rel="noreferrer"`；简历链接明确标注 PDF。
- 若开源代表性 PR 缺失，使用剩余已合并贡献补位；若不足三项，展示现有数量而不是占位符。
- Logo 保留替代文本；装饰图形继续对辅助技术隐藏。

## 测试与验收

- 组件单测覆盖主标题、三个 CTA、实习三条摘要与细节展开、代表性 PR 派生、唯一标题层级。
- 内容测试确保首页不出现未经验证的 Trending 荣誉，并保证已合并统计只计算 merged 状态。
- E2E 覆盖 1280×720 首屏关键信息、简历链接、三家公司扫读、工程细节展开、项目 Tab、开源代表性/完整列表、博客与联系入口。
- 自动检查重复 `id`、横向溢出、axe 严重问题、reduced-motion 动效关闭。
- 最终运行 `NEXT_PUBLIC_SITE_URL=https://portfolio.example.test pnpm verify`，再以本地生产构建检查关键滚动位置和浏览器控制台。

## 非目标

- 不重写博客系统、MDX 管线、SEO/RSS 或 Vercel 部署配置。
- 不新增移动端视觉方案。
- 不新增无法从公开链接或用户材料核验的数字、奖项和业务结果。
- 不复制参考网站的源代码、品牌资产或独特视觉标识。
