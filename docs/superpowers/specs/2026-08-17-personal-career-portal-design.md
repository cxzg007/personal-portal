# AI Agent / 后端开发个人求职门户设计方案

日期：2026-08-17  
状态：已确认，等待书面方案复核

## 1. 项目目标

本项目面向 AI Agent / 后端开发方向的校招场景，建立一个兼具专业可信度与视觉辨识度的个人门户。网站应让招聘者在 1–2 分钟内理解候选人的核心优势，并能继续深入查看实习贡献、后端工程能力、系统设计案例和技术写作。

核心叙事按以下顺序展开：

1. 实习经历是主要能力证据。
2. 后端工程与系统设计是能力底座。
3. 技术博客用于证明持续思考、表达与复盘能力。

网站借鉴参考站点以单页滚动串联个人信息和经历的思路，但不复刻其具体视觉或交互。最终采用“沉浸式叙事长页 + 局部工程控制台元素”，平衡校招信息效率和个性表达。

## 2. 成功标准

- 招聘者在首屏即可确认姓名、目标岗位、学校、专业、学历、毕业年份、求职状态和联系方式。
- 招聘者可以在两次操作内看到完整实习经历或下载 PDF 简历。
- 首页最突出的内容是实习成果，且每段经历能够说明问题、行动、个人贡献与结果。
- 网站通过轻量 3D Agent 网络建立记忆点，但动画不阻塞阅读或导航。
- 移动端、低性能设备、慢网和 WebGL 失败时仍可完整浏览核心内容。
- 博客文章具备良好的阅读、搜索引擎收录和技术内容表达能力。

## 3. 受众与使用场景

### 3.1 主要受众

- 校招 HR：快速判断教育背景、岗位匹配度、实习公司与成果。
- 技术面试官：深入查看技术决策、系统架构、难点和个人贡献边界。
- 用人团队负责人：评估工程成熟度、交付意识、成长潜力和表达能力。

### 3.2 典型路径

HR 路径：首屏身份摘要 → 实习经历 → 下载简历或联系。  
技术面试官路径：首屏 → 实习详情 → 系统设计案例 → GitHub / 博客。  
内容访问路径：搜索或外链进入文章 → 查看作者身份 → 返回首页了解经历。

## 4. 信息架构

主导航为：

`首页 / 实习 / 系统设计 / 博客 / 关于 / 简历`

教育经历不设置独立板块。完整教育摘要直接放在首屏姓名下方，格式为：

`学校 · 专业 · 学历 · 预计毕业年份`

若存在多段教育经历，首屏最多展示两行。排名、奖学金、竞赛或核心课程只有在能明显增强竞争力时，才以小型标签补充。

### 4.1 首页内容顺序

1. Identity Hero
2. Impact Metrics
3. Internship Timeline
4. System Case Studies
5. Featured Writing
6. Profile & Contact

### 4.2 博客结构

- `/blog`：文章列表、标签筛选和站内搜索。
- `/blog/[slug]`：文章详情、目录、代码高亮、阅读进度、上一篇与下一篇。
- RSS 和站点地图支持内容订阅与搜索引擎发现。

## 5. 页面与组件设计

### 5.1 Identity Hero

首屏由清晰的文字信息层和独立的 3D 背景层组成。文字层包含：

- 姓名与简短英文标识。
- 目标岗位：AI Agent / 后端开发。
- 完整教育摘要。
- 一句个人定位，重点指向实习交付和后端系统能力。
- 当前校招状态。
- 邮箱与 GitHub。
- “查看实习经历”和“下载简历”两个主操作。

任何核心文字都必须是可选择、可复制的 HTML 内容，不放入 Canvas。

### 5.2 Agent Network Scene

首屏背景是一个持续运行的抽象 Agent 网络：中心节点代表候选人，外围节点对应实习、Agent、后端、系统设计与博客。节点之间存在缓慢的数据流、轻微呼吸和鼠标视差。

向下滚动时，网络逐步拆解并转化为实习时间线的视觉引导。动画只承担空间连续性，不承担核心信息展示。

### 5.3 Impact Metrics

展示 3–4 个能够被简历或经历证明的量化结果，例如：

- 参与或负责的核心系统数量。
- 性能、稳定性或成本改善幅度。
- 服务规模、请求量或任务吞吐量。
- 实习交付、开源贡献或技术文章数据。

指标必须具备明确口径；无法证明的数字不进入该区域。

### 5.4 Internship Timeline

这是首页核心模块。每段实习统一包含：

- 公司、团队、岗位与时间。
- 业务背景和需要解决的问题。
- 候选人采取的关键行动。
- 个人负责范围及与团队协作边界。
- 量化结果或可验证的交付结果。
- 核心技术栈。

默认视图保证快速浏览；展开视图补充技术难点、架构片段与取舍。模块可使用 `Shipped`、`Optimized`、`Deployed` 等工程状态标签，但不让英文装饰影响中文理解。

### 5.5 System Case Studies

首页只展示 2–3 个代表性案例。每个案例包括：

- 业务问题与约束。
- 系统边界和上下游关系。
- 关键架构图。
- 技术选型及放弃其他方案的原因。
- 可靠性、性能、扩展性或成本方面的权衡。
- 候选人的个人贡献与最终结果。

架构图随滚动逐步点亮调用链；同时提供静态完整图，避免动画成为理解前提。

### 5.6 Featured Writing

首页精选 3–4 篇最能证明岗位能力的文章，优先顺序为：

1. Agent 工程实践。
2. 后端架构与系统设计。
3. 性能优化或可靠性建设。
4. 故障复盘与工程方法。

### 5.7 Profile & Contact

收尾区域包含不超过两段的个人介绍、求职状态、邮箱、GitHub、其他专业平台和简历下载。避免加入与校招目标无关的复杂社交信息。

## 6. 视觉设计系统

### 6.1 视觉定位

整体呈现“一套正在运行的个人工程系统”，而不是传统简历页面叠加动态背景。基调为沉浸、克制、精确和可信。

### 6.2 色彩与字体

- 背景：近黑蓝。
- 正文：高对比冷白和中性灰。
- 主色：冰蓝。
- 强调色：少量紫色，仅用于焦点和状态。
- 中文正文：现代无衬线字体，优先保证长文可读性。
- 英文标题与数字：使用带轻微技术感但不过度装饰的字体。

### 6.3 卡片与光效

- 深色半透明面板、细边框和有限的背景模糊。
- 光晕只用于关键指标、当前节点和交互焦点。
- 悬停反馈以轻微纵深、连接线和补充信息为主。
- 不使用持续闪烁、高饱和霓虹或大面积玻璃拟态。

## 7. 动效与降级策略

- 首屏文字立即可读，3D 场景延迟加载。
- 桌面端使用完整轻量 3D 网络和适度视差。
- 移动端降低粒子数量、渲染精度和交互频率。
- 低性能设备使用预渲染动态背景或静态 SVG 网络图。
- WebGL 初始化或资源加载失败时自动切换静态方案。
- 尊重系统的“减少动态效果”设置，关闭非必要视差与滚动联动。
- 用户无需等待动画结束即可浏览、点击或下载简历。

## 8. 内容管理方案

### 8.1 博客

首期采用 Markdown/MDX 与 Git 管理，不建设内容后台。选择依据：

- 技术文章需要代码、表格、架构图和可选的交互组件。
- 静态生成有利于性能、SEO 和低成本部署。
- 内容与代码可以统一版本管理和回退。
- 当前是单人维护，登录、权限、审核和数据库属于不必要复杂度。

发布流程为：创建文章 → 本地预览 → 提交 → 自动部署。

为未来接入 Headless CMS 预留内容适配层，但首期不实现 CMS 集成。文章元信息统一包含标题、摘要、发布日期、更新时间、标签、封面、草稿状态和 SEO 描述。

### 8.2 结构化个人数据

个人信息、教育经历、实习经历、成果指标、技术栈和系统案例分别存放在类型明确的数据文件中。页面组件只消费结构化数据，不把大段经历直接写死在组件内。

## 9. 技术架构

推荐技术组合：

- Next.js + TypeScript：路由、静态生成、SEO 和页面框架。
- React Three Fiber / Three.js：首屏 3D 场景。
- Framer Motion：滚动转场和二维界面动效；与 React 组件组合直接，首期不引入第二套动效框架。
- Tailwind CSS + CSS Variables：设计令牌和响应式样式。
- MDX：博客内容和自定义技术内容组件。
- 静态类型数据文件：个人资料、经历和案例。
- Vercel：自动构建与部署，首期利用其对 Next.js 的直接支持降低运维成本。

数据流：

```text
个人资料与实习数据 ──→ 首页组件 ──→ 静态页面
MDX 博客文章 ───────→ 内容解析 ──→ 博客列表与详情页
3D 场景配置 ────────→ WebGL ────→ 首屏沉浸式背景
                                  └→ 失败时切换静态 SVG
```

博客页面不加载 3D 引擎，避免影响阅读和首屏性能。

## 10. SEO、分享与分析

- 每个页面具有独立标题、摘要、规范链接和分享卡片。
- 使用适合个人资料与文章的结构化数据。
- 简历使用稳定的公开路径，更新文件时保持链接不变。
- 生成博客站点地图和 RSS。
- 邮箱、GitHub、岗位和毕业年份均能被普通页面抓取。
- 可加入隐私友好的访问统计，只收集页面访问和匿名交互事件，不采集简历访问者的敏感信息。

## 11. 性能预算

- HTML 和核心样式优先返回，3D 与非关键动画后加载。
- 3D 模型、纹理、字体和脚本在实施计划中设定独立体积预算。
- 图片使用响应式尺寸和现代格式。
- 页面滚动期间避免高频布局计算。
- 博客详情页保持无 3D、低脚本负担。
- 核心网页指标、移动端耗电和中低端设备流畅度作为验收条件。

## 12. 错误处理

- WebGL 不可用：显示静态 SVG 网络背景。
- 3D 资源加载超时：停止重试，保留完整首屏文字和操作。
- 文章元信息错误：构建阶段失败并指出具体文章，避免发布残缺页面。
- 简历文件缺失：构建或自动检查失败，避免线上出现无效下载按钮。
- 外链不可用：不影响站内内容浏览，并通过定期链接检查发现。
- JavaScript 受限：基本身份信息、实习摘要和联系方式仍存在于服务端生成的 HTML 中。

## 13. 测试与验收

### 13.1 功能

- 导航、锚点、博客筛选、文章目录、外链和简历下载正常。
- 实习详情与系统案例展开后信息完整。
- MDX 代码块、表格、图片和架构图正确渲染。

### 13.2 响应式与兼容性

- 覆盖桌面、平板和主流手机宽度。
- 检查支持与不支持 WebGL 的环境。
- 检查触摸、鼠标和键盘导航。

### 13.3 性能与降级

- 验证慢网、低性能设备和 3D 加载失败场景。
- 验证系统“减少动态效果”设置。
- 确认首屏核心文字和按钮不受场景加载状态影响。

### 13.4 内容质量

- 校验实习时间、成果数字、个人贡献边界和技术名词。
- 校验教育信息、联系方式、GitHub、简历及所有外链。
- 保证页面内容与 PDF 简历不存在事实冲突。

### 13.5 可访问性

- 验证文字对比度、可见焦点、键盘顺序和语义标题层级。
- 非装饰图片和架构图提供文本说明。
- Canvas 仅作为装饰，不承载唯一信息。

## 14. 首期范围

首期包含：

- 沉浸式单页首页。
- 首屏完整教育摘要。
- 实习时间线及展开详情。
- 2–3 个系统设计案例。
- MDX 博客列表与文章详情。
- 关于与联系区域。
- PDF 简历下载。
- 响应式布局、SEO、RSS、性能降级和基础匿名统计。

首期不包含：

- 内容管理后台。
- 用户账户、评论和点赞。
- 多人协作与审核流程。
- 复杂可操控的 3D 世界或游戏化探索。
- 与求职目标无关的社交动态聚合。

## 15. 实施前内容准备

实施开始前，由内容方提供以下真实资料：

- 姓名、英文名或技术 ID、头像或个人视觉素材。
- 学校、专业、学历和预计毕业年份。
- 目标岗位、一句话定位和校招状态。
- 每段实习的公司、团队、岗位、时间、业务背景、个人行动和结果。
- 3–4 个可验证的成果数字及统计口径。
- 2–3 个系统设计案例的背景、架构、决策、贡献和结果。
- 邮箱、GitHub 和需要展示的专业平台。
- PDF 简历文件。
- 首批精选文章或文章主题。

个人经历中的保密信息必须经过脱敏；不得展示内部地址、密钥、未公开数据、客户信息或违反实习协议的架构细节。

## 16. 最终决策摘要

- 求职目标：AI Agent / 后端开发校招。
- 内容优先级：实习经历 > 后端工程与系统设计 > 技术博客。
- 视觉方向：沉浸式 3D 长页，吸收工程控制台元素。
- 教育信息：完整显示于首屏，不设独立教育板块。
- 博客：Markdown/MDX + Git，无管理后台，预留 CMS 适配接口。
- 技术原则：核心信息静态可读，3D 延迟加载并可完整降级。
- 首期原则：求职信息效率优先，视觉效果用于增强叙事和记忆点。
