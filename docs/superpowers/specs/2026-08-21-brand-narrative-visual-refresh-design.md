# 个人求职门户品牌化工程叙事视觉升级设计

日期：2026-08-21

## 1. 目标与范围

本轮在现有 Next.js 个人求职门户上进行视觉与内容升级，服务 2027 届 AI Agent / 后端开发校招展示。设计参考 `https://xianchaoqian.com/` 的技术身份优先、品牌化经历卡和滚动叙事方式，但不复制其布局或视觉资产。

升级目标：

- 将冷蓝科技风调整为更有活力和向上感的深色暖色系统。
- 让技术名 `cxzg007` 成为首屏最强身份标识，真实姓名作为次级署名。
- 将三段实习升级为具有公司品牌识别、核心问题、关键决策和交付价值的工程叙事。
- 将 Semantica 开源贡献升级为独立品牌板块，补足项目背景、官方 Logo、公开贡献和项目荣誉。
- 在不虚构数据或业务成果的前提下，根据简历提升文案的信息密度和招聘价值。

本轮以 1280-1920px 桌面端为主要精修范围。移动端不新增复杂视觉和动效，但必须保留现有基础响应式能力：内容完整、操作可用、无横向溢出。

## 2. 设计原则

### 2.1 招聘阅读优先

招聘者应在短时间内识别技术身份、目标岗位、教育经历、实习公司和核心工程价值。动态效果用于引导阅读，不延迟或遮挡核心内容。

### 2.2 事实边界

实习文案以 `/Users/jiangjunjie.37/personal portal/resume(2).pdf` 和已经确认的公开信息为事实源。允许重组表达为“问题-决策-贡献-价值”，但不得添加无法验证的性能比例、业务规模、上线收益或职责范围。

Semantica 项目背景和 PR 状态以公开仓库为依据，并保留快照日期。个人身份明确为 Open-source Contributor，不暗示是维护者。荣誉按用户提供截图的原文展示，不称为 GitHub 官方认证奖项。

### 2.3 渐进增强

页面语义内容由服务端输出。滚动、3D、悬停和计数动画均为渐进增强；减少动态效果、低性能设备和移动端可以降级到静态或轻量版本。

## 3. 视觉系统

### 3.1 色彩

全站使用“深炭黑 + 琥珀橙 + 珊瑚红 + 暖米白”：

- 页面底色：炭黑与深棕黑，避免纯黑造成压抑。
- 主强调色：琥珀橙，用于主要按钮、时间线、关键数据、工程节点和焦点状态。
- 辅助强调色：珊瑚红，用于重要结果、活动状态和局部光晕。
- 主要文字：暖米白；次级文字使用带暖色倾向的灰色。
- 公司与项目品牌色仅在对应品牌卡内部使用，并由全站暖色边框和表面色统一。

不得依赖仅靠颜色传达状态。品牌色、结果状态和交互状态必须同时提供文字或结构提示。

### 3.2 表面与排版

- 卡片采用深色半透明表面、细暖色描边和克制的玻璃质感。
- 大标题保持清晰的无衬线技术感，正文优先保证中文可读性。
- 数字、状态和工程节点可使用等宽字体形成系统界面感。
- 光晕集中在首屏、时间线连接和重点品牌卡，不让所有元素同时发光。

## 5. 实习品牌化工程叙事

实习区从普通时间线升级为三张大型公司品牌卡。每张卡包含：

- 官方公司 Logo、公司名、团队、岗位和时间。
- 一句核心价值标题。
- 三节点工程链路：核心问题 -> 关键方案 -> 交付价值。
- 2-3 条最具区分度的个人贡献。
- 次级技术栈。
- 可展开的业务背景、关键行动、个人贡献和交付结果。

Logo 使用公开可用的官方品牌素材，以本地静态文件随站点部署。不得自行重绘、扭曲或改变标志比例；每个 Logo 提供准确替代文本。

### 5.1 京东

核心价值标题：

> 构建本体驱动的 AI 数据智能平台，让 LLM 在受控语义边界内完成查询、规则生成与业务回写。

默认重点：

- 建立业务实体到物理 Schema 的完整映射治理生命周期。
- 使用 OntologyGraph 与 BFS 支持跨实体多跳关系推导。
- 通过语义 SQL、确定性映射和 Schema 编译控制 AI 直接操作业务数据的风险。
- 使用缓存、主动失效和兼容治理支撑平台持续迭代。

三节点链路建议为：`业务语义建模 -> 受控 Agent 执行 -> 确定性回写`。

### 5.2 智元机器人

核心价值标题：

> 为机器人多传感器数据与企业知识资产构建可靠的流式回放和 Agent 记忆后端。

品牌卡展开后分成两个明确项目模块：

- `clip-player`：MCAP HTTP/WebSocket 双通道回放、对象存储分级读取、并发 seek、会话一致性和慢消费者隔离。
- `agibot_retriever`：三级实体去重、MySQL/Milvus 跨存储一致性、幂等抽取、故障自愈和关系约束。

默认重点应同时体现 Go 流式系统能力与 Agent / 知识图谱能力，避免把两项工作压缩为模糊的“平台开发”。

三节点链路建议为：`多源数据接入 -> 可靠流式/知识处理 -> 可恢复 Agent 服务`。

### 5.3 中国船舶集团 722 研究所

核心价值标题：

> 面向海上通信网络组建与受损恢复，完成算法建模、仿真验证和无人机集群通信方案论证。

默认重点：

- 链路建立、波束匹配和网络重构算法设计。
- 围绕通信建立成功率、恢复时延和链路稳定性完成仿真评估。
- 将研究问题抽象为可验证算法路径，并完成项目交付和技术文档。

三节点链路建议为：`通信场景建模 -> 重构算法与仿真 -> 方案验证交付`。

## 6. Semantica 开源品牌板块

Semantica 从普通案例卡升级为独立的开源贡献板块，使用项目官方 Logo 和紫色品牌点缀，但由暖色表面系统统一。

板块明确显示 `Open-source Contributor · cxzg007`。

动态视觉使用知识图谱链路：`Context -> Knowledge Graph -> Reasoning -> Provenance`，进入视口后连接并点亮 `cxzg007 contributions` 节点。

## 7. 动效系统

- 首屏网络使用暖金节点、橙红粒子和向上连接趋势。
- 成果指标进入视口时依次点亮或计数，动画只执行一次。
- 实习卡进入视口时依次显现 Logo、核心标题和三节点链路。
- 悬停只增加暖色边缘光和轻微纵向位移，不使用夸张缩放。
- 滚动光晕从首屏网络传递到成果指标、实习时间线和开源板块，形成连续叙事。
- `prefers-reduced-motion` 下不注册滚动动画监听，保留所有静态内容和状态。
- 移动端不运行新增复杂动效，只保留必要的展开交互和静态品牌信息。

## 8. 内容模型与组件边界

现有内容模型扩展以下字段或等价结构：

- 公司/项目 Logo 本地路径和替代文本。
- 品牌色或受控品牌主题标识。
- 核心价值标题。
- 三节点工程链路。
- 默认重点贡献。
- 开源项目背景、贡献身份、荣誉和荣誉说明。

内容校验必须拒绝缺少 Logo 替代文本、空核心标题、非三节点链路、空重点贡献或不完整荣誉记录。

组件保持清晰边界：

- `Hero` 只负责身份、教育与首屏操作，3D 继续通过独立延迟加载边界提供。
- 实习品牌卡负责公司叙事和展开状态；Logo 展示与工程链路可以拆成独立无状态组件。
- 开源品牌板块负责 Semantica 项目背景、荣誉和公开贡献，不与博客文章加载逻辑耦合。
- 滚动增强继续由首页单一客户端边界管理，使用 `requestAnimationFrame` 节流并在卸载或减少动态效果时完整清理。

所有公开内容由本地 JSON/MDX 提供，不增加 CMS 或管理后台。

## 9. 错误处理与降级

- Logo 文件缺失必须在内容校验或生产构建时失败，不允许线上空白占位。
- WebGL 初始化失败时使用暖色静态网络，不影响首屏文字和操作。
- JavaScript 不可用时，实习核心内容、Semantica 项目背景和链接仍通过服务端 HTML 可读。
- 展开区域必须使用原生按钮和 `aria-expanded` / `aria-controls`，键盘可操作并保持焦点可见。
- 外部 GitHub 链接失败不会影响页面其余内容；站点不在运行时请求 GitHub API。

## 10. 验收标准

### 10.1 视觉与交互

- 1440x900 和 1920x1080 为主要桌面视觉验收尺寸。
- 390px 移动端内容完整、按钮可用且没有横向溢出。
- `cxzg007` 是首屏最大身份标题，真实姓名清晰可见但层级更低。
- 三家公司均显示清晰的官方 Logo、核心价值标题和三节点工程链路。
- Semantica 显示官方 Logo、项目背景、两项荣誉、贡献身份、PR 数据和两个外部入口。
- 减少动态效果下不出现 Canvas，核心内容和品牌信息仍完整。

### 10.2 可访问性与性能

- 文字与交互状态达到 WCAG AA 对比度。
- 公司 Logo 具有准确替代文本，装饰性图形对辅助技术隐藏。
- 键盘可以按阅读顺序访问主要操作、所有实习展开按钮和开源链接。
- 博客列表和文章页面不加载 Three.js、React Three Fiber 或首页品牌动效代码。
- 新增动效不产生持续无界监听、定时器或显著布局抖动。

### 10.3 工程门禁

- 内容 Schema 和新组件具有单元测试。
- 端到端测试覆盖身份层级、公司 Logo、实习展开、Semantica 背景/荣誉/链接、减少动态效果和基础移动端可用性。
- 通过 lint、TypeScript、内容验证、生产构建、无障碍和现有完整 Playwright 测试。
- Vercel 生产构建继续使用现有 URL 回退逻辑和 pnpm 锁定版本。
